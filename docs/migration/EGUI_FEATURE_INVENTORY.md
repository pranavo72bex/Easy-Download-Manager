# egui feature inventory

What dm's egui window does today, feature by feature, so a GPUI presentation
can be built to do the same. Read from the code on branch `gpui-migration`
(2026-11-09, at `aea95ae`), not from the docs alone. The contract rows are
those of [docs/behaviour-contract.md](../behaviour-contract.md); every one of
its 64 rows (B01 to B65; there is no B58) is mapped in the index at the end.

How to read the tables:

* **egui module(s)**: paths under `desktop/crates/dm-desktop/` (`src/…`,
  `tests/…`). `main.rs`, `tray.rs`, `platform.rs`, `window.rs`, `hidden.rs`,
  `login.rs`, `signals.rs`, `dock.rs` and `opened.rs` are modules of the binary,
  not of the `dm_desktop` library.
* **Application API used**: real names in `dm_shell::app` (`Backend`,
  `Session`, `Snapshot`, `commands`, `rules`, …), `dm_shell` (settings, host,
  register, lists, dialup) and `dm_core` (`Entry`, `State`, `Id`, `Category`,
  `Schedule`). `Command::X` is `dm_shell::app::commands::Command`.
* **Target GPUI view/component**: a proposed name only; nothing of GPUI exists
  yet.
* **Test coverage**: `kt` = egui_kittest test, by file and function (all under
  `tests/`); `HQA Bxx` = the row `scripts/human-qa.py` checks in the real
  window; `unit` = a `#[cfg(test)]` test in the source file named. "None found"
  means no test was found by name or wording; it may still be reached by a
  broader test.
* **Migration status**: "egui only" everywhere (nothing is ported yet);
  "needs investigation" is added where the implementation could not be pinned
  down.

2. **The control port's `ui.*` methods**, which read and drive egui itself:
   `ui.texts` reads epaint text shapes of the last frame; `ui.click`,
   `ui.scroll`, `ui.type` and `ui.key` feed egui `RawInput` one step a frame;
   `ui.inspect` returns rows' rects as drawn and the dialogs by egui window
   title; `ui.screenshot` asks eframe for the frame's pixels; `ui.windows`,
   `ui.window` and `ui.move_window` use egui viewports. `scripts/human-qa.py`
   and the MCP tools `dm_screen`, `dm_click`, `dm_type`, `dm_press_key`,
   `dm_move`, `dm_screenshot`, `dm_inspect` depend on these answers keeping
   their shape.
3. **The headless stand-in `egui::Context`.** `--headless` and a login launch
   (`src/hidden.rs`) run `DmApp::logic` against an `egui::Context` with no
   window; `src/app/scheduled.rs` does too in a test. A GPUI port should run
   the application's tick (`Session::read`, `schedule_tick`, `Hands::next`,
   `control_api::answer`) without any UI context.
4. **Baseline pictures.** `docs/behaviour-baseline/` (macOS set),
   `windows/` and `linux/` (empty window, Add URL, Download details), compared
   by `scripts/human-qa.py` for B25 at 1% of pixels. Any GPUI rendering will
   differ; new baselines need the maintainer's approval (the contract's rule).
5. **HQA B52 reads source.** `scripts/human-qa.py` checks that
   `desktop/crates/dm-desktop/src/tray.rs` names
   `Command::SpeedLimiterSettings`; moving the tray code moves that check.
6. **Vendored crates patched for egui.** `desktop/vendor/egui-winit`
   (input to dialog windows, `OTHER_WINDOWS_INPUT`) and `desktop/vendor/eframe`
   (an AccessKit adapter per window) exist only for egui. `desktop/vendor/winit`
   (X11 and Wayland link drops, Wayland drag out) matters to any winit-based
   window and would need an equivalent if GPUI does not use winit.
7. **Dialogs as egui viewports.** `src/dialogs/apart.rs` and `frame.rs` make
   each dialog an egui viewport, with an embedded fallback for the test
   harness (`Context::embed_viewports`); modality is an egui modal layer plus
   a covering area (`hold_the_window`).
8. **egui-only view state in `DmApp`** (`src/app/mod.rs`): selection, anchor,
   cursor, sort, hidden columns and order, row rects, list clip, popup state,
   focus ring, `Dialogs` (`src/dialogs/mod.rs`). These are the presentation's
   to own again; the application does not hold them.
9. **Key matching.** `src/commands.rs` turns `Chord`s into
   `egui::KeyboardShortcut`s and works around egui matching a shortcut with an
   extra Shift; GPUI actions and key bindings replace it.
10. **Text shaping workarounds.** `src/bidi.rs` (right-to-left words reordered
    for egui's shaper) and `src/theme/scripts.rs` (system fonts loaded into
    egui for CJK and other scripts) may become unnecessary or different under
    GPUI's text system; the catalogs' fonts test (`tests/i18n.rs`) checks
    egui's fonts.
11. **Theme tokens applied to egui `Visuals`/`Style`** (`src/theme/apply.rs`),
    the icon font loaded into egui (`src/icons.rs`), and egui's zoom factor as
    the text size.
12. **egui-specific platform glue:** `src/drops.rs` swaps methods on winit's
    macOS window delegate and registers an OLE drop target on winit's Windows
    window; `src/dock.rs` adds a method to winit's application delegate;
    `src/xdnd.rs` reads the pointer from winit. Each assumes winit owns the
    window.
