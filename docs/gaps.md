# Gaps

Every known shortfall between dm and a production-ready download manager,
ranked. This is the work list: take the top open item, close it with
evidence (a test or a check that ran), and record the date in its entry.
When a gap closes, move it to "Closed" with what proved it.

Status words, as in `docs/parity.md`:

| Status       | Meaning                                                      |
|--------------|--------------------------------------------------------------|
| OPEN         | Nothing done, or done but never run                          |
| PARTIAL      | Works and is tested, but not everywhere it must              |
| BLOCKED      | Needs something this project cannot get for free, or a person |

## Is dm production ready?

Not yet, as of 2026-10-17. Every menu item, toolbar button and row-menu
item is clicked by its name in `window.rs` and checked for what it does. The engine, the window, the queue
and the extension are tested end to end on macOS arm64 in Chrome and
Firefox, the Linux client in Debian and Ubuntu containers, and the Arch
package on arm64 and (emulated) x86_64. What stops a release is P0: Windows
has run only in CI's test job, CI is not yet green on every job, and nothing
is signed.

|---------------------|-----------------------------------------------------------------------------------------|
| Chrome              | `chrome-check.py` fetches Chrome for Testing into `~/.cache`; nothing is installed       |
