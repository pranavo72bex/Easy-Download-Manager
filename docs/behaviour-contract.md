# Behaviour contract

What a person does in dm and what must then happen. This list is fixed:
**no change by an AI or anyone else alters a behaviour here unless the
maintainer has approved that change in words.** An approved change edits its
row here, and the baseline pictures if the window changes, in the same
commit, which names the approval.

Every row is checked by `scripts/human-qa.py`, which drives the real window
and Microsoft Edge the way a person does, slowly and in sight, and fails if
any row below was not checked. Run it whole, not a part of it: before a merge,
after any change to `desktop/`, `browser/` or `extension/`, and whenever
someone asks for QA.

    python3 scripts/human-qa.py

The target is reference A, the best-known commercial download manager for
Windows. The "Reference A" column says whether dm already does what it does;
a row that differs stays as dm has it until the maintainer decides.
Recorded 2026-10-29 from the merged `main`, where every row passed.

## How a file is fetched

| ID | Situation | What must happen | Reference A |
|---|---|---|---|
| B06 | Any file from a server that takes ranges | Several connections (8 by default); a connection with nothing left halves the piece that would take longest to finish at the pace it is going, where that is longer than a new request is worth (a tenth of a second, or twice what a request waits for its first byte), judged once the ranges still under way have taken up the share of one just ended; a piece about to end, or one whose answer is on its way, is left to its own connection (since 2026-11-11, by the maintainer's standing instruction to fix bugs and improvements without asking: halving however soon a piece would end fetched 4 to 9% of a fast 512 MiB file twice; gaps rows 171 and 177). The number set is a ceiling: at most 8 open at once, and past them one more (then two, four…) only while the last ones added raised the total speed by at least half of what a connection brought; when they did not, they are given back after the piece they hold, and tried again later (since 2026-11-10, at the maintainer's word of that day, "fix the download speed problem", choosing the adaptive ceiling; gaps row 168) | same |
| B07 | A fast server that keeps connections open | Finished connections take the next piece: more requests than connections | same |
| B08 | A server that holds each connection to a low speed | Every connection is used; 32 MiB at 2 MiB/s a connection finishes in a few seconds, not sixteen. Past 8, each is added as it raises the speed (B06), so such a server gets all of them; one that shares a single speed among them all gets 8 | not documented |
| B09 | A server that allows two connections at once and answers 503 to more | The refusals are absorbed and the file completes | same (fewer connections for such servers) |
| B10 | A server that does not take ranges | Fetched on one connection, whole | same |
| B11 | A server that says the file is longer than it sends | The file completes; it does not stay "running" | not documented |
| B12 | An address that redirects | Followed; saved under the name of what it reached | same |
| B13 | A server that names the file (Content-Disposition) | Saved under that name ("Report 2026.pdf") unless the person says No to the question of B39 | same |
| B39 | A server names the file differently from the address (`/dl?id=7` answered with "Report 2026.pdf") | A question, "Name sent by the server": "The name to save the file was dl, but the server sent Report 2026.pdf. Save the file with the name received from the server?", "Use Report 2026.pdf" / "Keep dl". "Use Report 2026.pdf" saves it as "Report 2026.pdf"; "Keep dl" saves it under the address's name (verbs, not Yes / No, at the maintainer's word of 2026-11-12, gaps row U31). Not asked when the names agree, for a name the person typed in Download details, or for links added together by "Download all links". Added 2026-11-01 at the maintainer's word | same |
| B40 | An address that ends like a file (`.zip`) answers with a web page | A question, "Web page instead of the file": "The requested file looks like an HTML web page. Would you like to continue downloading it and save it as an HTML page?", "Save as HTML" / "Don't download". "Save as HTML" saves the page as `<name>.html`; "Don't download" removes the row and keeps nothing (verbs, not Yes / No, at the maintainer's word of 2026-11-12, gaps row U31). Where nothing can ask (the command line, an AI client) the row fails with "web page rather than the file", as before. Added 2026-11-01 at the maintainer's word. Since 2026-11-06 an address typed in that is a web page and not a file (nor a video site's page dm reads itself) is asked about the same way, where it was refused; its row's words still say a video comes from the browser's Download video button (gaps row 136, the maintainer's word of 2026-11-06 to do what is better for the person) | same |
| B14 | An address that answers 404 | The row fails and says "This link no longer works", with the server's answer, and a window tells it once (B41) | same |
| B41 | An address that answers 404, the row having failed | Once, a window "The file doesn't exist": "The requested file doesn't exist.", Details: "HTTP/1.1 404 Not Found", OK and Update download link (which opens that dialog for the row; added at the maintainer's word of 2026-11-12, gaps row U10). It does not come back for the same row. Added 2026-11-01 at the maintainer's word | same |
| B15 | Every download that completes | Its bytes are exactly the server's | same |
